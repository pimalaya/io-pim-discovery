# pimalaya-stream 0.3

The two built-in HTTP factories follow pimalaya-stream's renamed transport: `StreamStd::connect_tcp(host, port)` and `StreamStd::connect_tls(host, port, &tls)` are now `Stream::connect_tcp(host, port, TcpConnectOptions::default())` and `Stream::connect_tls(host, port, TlsConnectOptions { tls, ..Default::default() })`, with the `std` module gone from the import path. Three doc links naming the old path followed it.

Behaviour changed underneath rather than here: reads and writes on those streams now retry a socket reporting it is not ready, for a minute before giving up, and a connect arms a read deadline to match. A discovery probe against a host that accepts the connection and then says nothing therefore ends on its own, where it used to block for as long as the operating system allowed.

Capabilities moved: none. The stream pool, its per-endpoint reuse and its pluggable factories are unchanged.

Verified: `cargo check --all-features` and `cargo fmt` clean, and `pim-discovery email first` resolves Fastmail's IMAP, POP3 and SMTP endpoints live over the new transport.
