# base64 runs on base64-codec

The base64 crate gave way to base64-codec 0.1, as the family decided on 2026-11-03: src/pacc/discover.rs decodes the TXT record's `d` digest through `Base64Codec::decode_vec` and skips a record it did not read clean, since the codec decodes leniently and never fails; a digest of the wrong length still fails the constant-time comparison. The CLI's `main` calls `SimdCpu::install_detected()` first (simd-cpu 0.1, `std`, behind the `cli` feature), so this codec and io-http's run the detected backend. base64 0.23 stays in the tree only through pimalaya-cli 0.3.

Capabilities moved: none.

Verified: every mechanism feature alone with `--no-default-features`, the default build and `--features cli` checked clean, `cargo clippy --all-features --all-targets` clean, `cargo test --all-features` passed (45). No test covers the PACC digest, so `pim-discovery all test@fastmail.com` was run: Fastmail publishes PACC, and its configs came out tagged `pacc`, so the digest decoded and matched.
