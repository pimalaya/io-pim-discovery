# io-http 0.7

The io-http requirement moves from 0.6 to 0.7.0, released on 2026-11-13, and the lockfile holds that one version. Nothing in src/ or examples/ changed: the crate builds its requests through `Http11Send` and `Http11WellKnown`, never through `to_http_11_vec`, and uses neither the event stream parser nor `HttpAuthBearer`.

The break is in the types this crate hands out: `HttpRequest` and `HttpResponse` (src/shared/walk.rs, src/rfc9110.rs) and the `Http11SendError` and `Http11WellKnownError` its error enums wrap are the 0.7 ones, and `Http11SendError` gained `UnsupportedTransferCoding`, `TooManyInterimResponses` and `InvalidRequest`.

Behaviour changed underneath rather than here, for every probe, the redirect walk and DNS over HTTPS alike:
- up to 8 interim 1xx responses are skipped before the final one, 101 excepted;
- a chunk whose data is not followed by CRLF fails the exchange, and trailers are read, up to 64 KiB;
- a final transfer coding other than `chunked` fails the exchange;
- a request whose method, header name or header value would add a line fails at the first resume, before any write. Every header this crate sets is a literal, except `Host` in src/shared/http.rs, taken from a parsed `Url`.

No scripted fixture needed a fix: every one frames its body with `Content-Length`, none is chunked and none sends a 1xx.

Capabilities moved: none.

Verified: `cargo tree -i io-http --all-features` shows io-http 0.7.0 alone, `cargo test --all-features` passed (74), `cargo clippy --all-features --all-targets -- -D warnings` clean, `cargo build --no-default-features` clean, `cargo check --no-default-features --all-targets` clean for each mechanism feature alone, `client`, `stream`, `cli`, `rustls-aws`, `native-tls` and `native-tls,vendored`, and `cargo publish --dry-run --allow-dirty` packaged and built against the registry.
